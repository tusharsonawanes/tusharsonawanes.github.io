Jira Quality Gates

A set of automated checks that catch broken, missing, or inconsistent Jira data at every level of the hierarchy — Business Epic down to Story — before it quietly poisons a dashboard.

Role
Senior Scrum Master, reporting integrity
Tools
Jira · JQL
Scope
Five-level custom hierarchy
01 · Problem
02 · Approach
03 · Solution
04 · Impact

Problem

Every reporting layer above the team — velocity charts, quarterly rollups, executive dashboards — inherited whatever mess existed underneath: stories with no parent link, epics with no due date, orphaned issues sitting outside any portfolio. None of it was visible until a number on a dashboard looked obviously wrong, at which point tracing the bad record back through five hierarchy levels ate hours.

Approach

Rather than clean the backlog once and hope it stayed clean, the goal was a recurring gate — a check that runs on its own and flags what's broken before it reaches a report.

  • Mapped the failure modes worth catching at each level of the hierarchy: missing due dates, unlinked children, empty required fields, stale in-progress items
  • Wrote JQL-based queries for each failure mode, scoped per hierarchy level so a Business Epic issue doesn't get lost among Story-level noise
  • Prioritized issues that were silent — the ones that don't block a team's daily work but do quietly corrupt a rollup number

Solution

A recurring set of JQL-based gates, one per data-quality rule, run across the hierarchy and surfaced as a simple pass/warn/fail view — the same red/amber/green pattern used in delivery reporting, but pointed at the data feeding that reporting instead of the delivery itself. Anything flagged gets routed back to the item's owner rather than surfacing as an unexplained anomaly on a leadership dashboard weeks later.

Impact

Data-quality issues get caught and routed to an owner before they reach a report, not after someone questions a number in a leadership review. It has also made the underlying hierarchy migration and reporting work more defensible, since the data feeding it is checked on a cadence rather than assumed clean.
