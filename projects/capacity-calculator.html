Dynamic Capacity Calculator

Expected vs Actual capacity, refreshed live from Jira, so a PI planning room is negotiating with real numbers instead of a spreadsheet someone updated three weeks ago.

Role
Senior Scrum Master, capacity & PI planning
Tools
Jira API · Live data feed
Scope
Five teams, one value stream
01 · Problem
02 · Approach
03 · Solution
04 · Impact

Problem

Quarterly PI planning kept running into the same wall: the capacity numbers each team walked in with were manually compiled, already stale, and rarely matched what actually landed once the quarter started. Planning conversations spent more time arguing over whose number was right than deciding what to commit to.

Approach

Instead of another static capacity spreadsheet template, the goal was a calculator that pulled its own numbers.

  • Connected directly to Jira's API so committed capacity and actual delivered work refresh without anyone re-entering data
  • Built Expected vs Actual views per team and rolled up across the full value stream, so a PI room can see both the individual team picture and the aggregate at once
  • Added rolling averages (e.g. 3-sprint) rather than single-sprint snapshots, since one noisy sprint shouldn't reset a team's planning baseline

Solution

A live dashboard with three views used together: a monthly Teamwise velocity breakdown, a rolling 3-sprint average per team to smooth out noise, and a Fresh-vs-Spilled work split so a team's actual predictability — not just its raw output — is visible before commitments are made. Capacity utilization is shown against plan, month over month, so over- or under-commitment shows up immediately rather than at quarter-end.

Impact

PI planning conversations now start from one live, shared number instead of five separately-maintained spreadsheets. Teams carrying chronic spillover are visible before the quarter starts, not after, which has shifted planning discussions from "whose number is right" to "what do we actually do about this team's predictability."
