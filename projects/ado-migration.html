Jira → Azure DevOps Migration

Designed the target work-item hierarchy and board architecture in Azure DevOps, then sequenced a four-team migration off Jira without losing a sprint.

Role
Senior Scrum Master, migration lead
Tools
Jira · Azure DevOps
Team
4 teams, Data Tribe

02 · Approach
03 · Solution
04 · Impact

Problem

An organizational decision moved tooling standards from Jira to Azure DevOps. Four teams inside the Data Tribe had years of history, custom workflows, and reporting built on Jira — a naive migration risked losing backlog history, breaking sprint reporting, and stalling delivery mid-quarter.

Approach

Treated the migration as a delivery architecture problem first, and a data-move second.

  • Mapped every Jira issue type, workflow state, and custom field to an Azure DevOps equivalent before touching any data
  • Designed the target work-item hierarchy (Epic → Feature → PBI → Task) to match how the four teams actually plan, not a generic default
  • Wrote a migration runbook with a rollback point, sequenced team-by-team so only one team was in transition at a time

Solution

A documented Azure DevOps architecture — area paths per team, shared iteration cadence across the value stream, and dashboards rebuilt to match the reporting leadership already relied on — plus a runbook that let each team migrate in a single sprint boundary.

Impact

All four teams migrated without a missed sprint or a gap in delivery reporting. Backlog history and velocity trends carried over, so leadership reporting continued uninterrupted through the transition.
