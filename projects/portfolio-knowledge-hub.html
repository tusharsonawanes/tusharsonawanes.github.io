Multi-Portfolio Knowledge Hub

One place to find anything about any squad — documentation, who's on it, what they can do, and how to hire the next person — structured the same way the organization actually works: Portfolio → Program → Domain → Squad.

Role
Senior Scrum Master, enablement & knowledge ops
Tools
Confluence · Jira macros
Scope
Multi-portfolio, multi-domain

Problem

Knowledge about who worked on what, which squad owned which product area, and where to find team or project documentation was scattered across Confluence spaces that had grown organically — one per team, inconsistently structured, with no single view across a portfolio. Hiring, skills tracking, and innovation initiatives each lived in their own disconnected process, with no shared view of who was doing what across squads.

Approach

Rather than ask every squad to migrate into a shared space, the hub was built as a structural layer on top of what already existed.

  • Mirrored the real organizational hierarchy — Portfolio → Program → Domain → Squad — as the Confluence and Jira navigation structure, instead of an ad-hoc folder tree
  • Used Jira macros to pull live squad and project data into Confluence pages rather than maintaining a second, manually-updated copy
  • Folded in adjacent processes that squads needed anyway — hiring workflow, skillset evaluation, innovation drives — so the hub became the one place to look, not one more place to check

Solution

A Confluence space structured by the same Portfolio → Program → Domain → Squad hierarchy as delivery reporting, with team and product documentation living at the right level instead of scattered per-team. Jira macros surface live member and demographic analytics without manual upkeep, and the same space hosts the full hiring workflow and skillset evaluation drives, so onboarding a new hire or scoping an innovation initiative starts from the same structure as everything else.

Impact

Anyone looking for squad-level information — a new hire, a cross-domain lead, or someone scoping an innovation drive — now has one structural entry point instead of guessing which team's Confluence space might have it. Hiring and skills-evaluation processes that used to run informally per squad now sit inside the same hub other delivery information lives in.
