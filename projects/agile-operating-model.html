Enterprise Agile Operating Model

A Tribe → Domain → Value Stream → Team structure, adapted from Spotify-style principles, that gives four teams one coherent path from strategy to sprint.

Role
Senior Scrum Master, operating model design
Tools
SAFe · Spotify Model principles
Team
Data Tribe, Digital Touchpoint Analytics

02 · Approach
03 · Solution
04 · Impact

Problem

Four teams sat under the same value stream but planned independently, with unclear ownership between the tribe-level strategy and what each team actually pulled into a sprint. Priorities shifted inconsistently between teams working on the same products, Mein Magenta App and MagentaTV.

Approach

Rather than import a scaling framework wholesale, the model was built around how this specific value stream actually needed to make decisions.

  • Defined what belonged at each layer — Tribe (strategy), Domain (product grouping), Value Stream (Digital Touchpoint Analytics), Team (delivery) — so a decision has one obvious owner
  • Borrowed Spotify-model language for autonomy and alignment, adapted to SAFe cadences already in use at T-Systems
  • Piloted the model with one team before rolling it to all four, adjusting based on what broke

Solution

A documented operating model defining planning cadence, escalation paths, and decision ownership at each layer, plus a lightweight onboarding guide so a new team joining the value stream can adopt it without a lengthy ramp-up.

Impact

Cross-team prioritization conflicts dropped once ownership was explicit at each layer, and planning cadences aligned across all four teams inside the value stream.
